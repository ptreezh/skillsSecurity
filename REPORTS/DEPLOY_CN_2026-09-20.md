## 1. 背景与目标

现状公网链路（已于 v2.0 验收）：

```
┌────────────────┐  https  ┌──────────────────┐  https  ┌────────────────┐  docker exec  ┌────────────────┐
│ GitHub Pages   │ ──────▶ │ cloudflared 隧道  │ ──────▶ │ 后端 Express    │ ────────────▶ │ cmc-debug 容器 │
│ /skillsSecurity/│        │ trycloudflare     │         │ server/index.js │               │  └─▶ chain1   │
└────────────────┘        └──────────────────┘         │ :10002 (本机)    │               │    (chainmaker│
   api-config.json（守护自动维护 apiUrl）                 └────────────────┘               │     -node 容器)│
                                                                                          └────────────────┘
```

痛点：GitHub Pages 与 cloudflared 均非国内节点，国内访问不稳定（首屏加载慢、API 握手抖）。

目标：让**国内用户**稳定访问 AgentSkills 全链路，同时尽可能低成本、贴合宪法「零启动成本/零 token」精神。

---

## 2. 关键约束分析（决定方案可行性的三个事实）

### 约束① 链节点与 cmc 网关绑定本机 Docker（迁移的最大障碍）

- 后端链访问**不是 HTTP/RPC**，而是子进程 `docker exec cmc-debug cmc ...`（`server/chainmaker-client.js:76-77`）。
- cmc 的 SDK 配置、TLS 证书（`admin1.tls.crt` 等）、ABI 全部位于 **cmc-debug 容器内** `/work`（`chainmaker-client.js:78-84`）。
- `cmc-debug` 与链节点 `chainmaker-node` 为同机两个容器（P29 验收判据①：二者均 Up，`RestartPolicy=unless-stopped`）。
- **推论**：链访问是「进程 → Docker daemon → 容器 → 链」四级链。后端迁云 = `cmc-debug` + `chainmaker-node` 两个容器必须随之迁移或网络打通。

### 约束② 后端容器化已就绪，但依赖 docker.sock

- 仓库已含 `Dockerfile` + `docker-compose.yml`；compose 中 `agentskills-api` 挂载 `/var/run/docker.sock`，即 API 容器仍需调用宿主机 Docker 去 `docker exec cmc-debug`（`docker-compose.yml:26-27`）。
- **推论**：即便后端上云，云主机同样需要 Docker + cmc-debug + chainmaker-node 三件套同机（或改造 chainmaker-client 为远程网关，属额外开发）。

### 约束③ 域名与备案

- 现状无任何自定义域名。公网解析依赖隧道随机 URL（`public/api-config.json` 运行时维护）。
- 国内部署若要自有域名走标准端口（80/443）：
  - **大陆服务器 + 域名 → 必须 ICP 备案**（个人可备案，约 7–20 个工作日，免费）。
  - **OSS/COS 绑定自定义域名也要求域名已备案**（大陆区域）。
  - 香港/海外服务器 + 域名 → **免备案**，且香港线路国内访问质量尚可（推荐起步选项）。

## 3. 方案对比

| 方案 | 前端 | 后端 / 链 | 备案 | 成本（估） | 稳定性 | 复杂度 |
|------|------|-----------|------|-----------|--------|--------|
| **A. 前端国内化，后端不动** | `dist/` 传 OSS/COS + CDN（香港区域免备案） | 维持现状（本机 + cloudflared） | 免（香港 CDN + 域名可选） | ~10–100 元/年（CDN 按量） | 首屏快；**API 仍走隧道，不稳** | ★ 低 |
| **B. 全量迁移国内服务器**（推荐目标态） | Nginx 或 OSS/CDN | 服务器 Docker 三容器迁移（后端 + cmc-debug + chainmaker-node） | 大陆需备案；香港免 | ~300–1200 元/年（2C2G 香港轻量 ~30–100 元/月） | **全链路快** | ★★★ 高（chainmaker-node 迁移是硬骨头） |
| **C. 前端国内化 + 后端桥接** | 同 A | 后端不迁，VPS 跑 Nginx 反代 + frp client → 本机 frp server → 本机后端 → 链 | 大陆 VPS 需备案；香港免 | ~300–600 元/年 | 前端快；API 经 frp，比隧道稳，但依赖本机在线 | ★★ 中 |

> 说明：方案 B 的「全量迁移」难度不在后端，而在 **chainmaker-node 整链迁移**——需确认链数据卷、节点配置、证书可整体复制到新宿主机并能正常启动（若链上已有真实数据，强建议先备份并做恢复演练）。

## 4. 推荐路径（分两步，可独立决策）

### 第一步：方案 A（今天即可执行，零风险，先解决「打开快」）

1. `npm run build` 产出 `dist/`。
2. 阿里云 OSS / 腾讯云 COS 建桶（**香港区域**），开启静态网站托管，上传 `dist/`。
3. 可选：绑定自定义域名并开启 CDN（香港区域免备案；不绑定域名也可用临时外链）。
4. 后端零改动。**唯一代码级注意**：若前端将来用自定义域名，需把该域名加入后端 CORS 白名单：
   - 本机后端：启动时设环境变量 `CORS_ORIGIN`（`server/index.js` 已支持，`CORS_ORIGIN` 逗号分隔，见 `.env.example:37`）。
   - 容器后端：`docker-compose.yml:13` 的 `CORS_ORIGIN` 默认值扩展。
5. `public/api-config.json` 里的 `apiUrl` 仍指向隧道（守护自动维护，无需手改）。

结果：国内用户首屏秒开；API 请求仍偶发抖动（隧道侧），但整体体验显著优于现状。

### 第二步（规划）：方案 B —— 全量迁移（需先验证链可迁移）

前置验证（**不实操，先确认**）：
- [ ] `chainmaker-node` 容器用到的镜像、数据卷、启动参数、证书清单可导出。
- [ ] 在新宿主机（香港 VPS）复现容器启动，`cmc` 查询返回与现网一致。
- [ ] 链上数据备份策略（建议：迁移前导出 + 快照）。

迁移步骤（概览）：
1. 新宿主机（香港轻量 2C2G 起步）安装 Docker。
2. 迁移 `chainmaker-node` + `cmc-debug` 两容器（数据卷 + `.env` 链配置）。
3. `docker compose up -d` 起后端（现有 `docker-compose.yml` 已含 docker.sock 挂载，开箱可用）。
4. Nginx 托管 `dist/` 或继续用 OSS/CDN；域名解析 → 香港服务器（免备案）。
5. 更新 CORS 白名单与 `api-config.json` 的 `apiUrl` 为正式域名。
6. 移除 cloudflared 依赖（不再需要隧道）。
